# RAG 工具选择 Bad Case 与修复验收

日期：2026-10-13
范围：GPT-6-Luna 本机桥接、DSH、Edge 登录与单个合成患者；未使用真实患者数据。

## 起因

原始同源码浏览器验收提出了 2 次明确的本地医学证据请求，但 `search_medical_evidence` 只调用 1 次（1/2）。漏检那次仍正常完成了模型回答回合，却没有 `evidence.started`、证据卡或引用。另一次请求返回了 3 条证据，浏览器里 5 个引用 ID 都能对应到证据卡。

链路检查表明，Health Engine 和 823,450 段本地索引健康；失败发生在模型工具选择层。DSH 与桥接提示模型“应调用”检索工具，但 OpenAI 兼容请求仍用 `tool_choice: auto`。GPT-6-Luna 偶尔会直接生成回答，结束这一轮，而不调用已声明的工具。因此这是工具调用路由不确定性，不是索引缺失、检索服务错误或浏览器丢失证据。

## 修复

在本地 Codex 桥接层识别最新用户消息中的明确医学检索/引用意图。当 RAG 工具已声明、请求仍为 `auto`、没有严格 JSON 输出约束，并且当前用户回合尚未调用过 RAG 时，桥接将工具选择收紧为 `search_medical_evidence`。模型仍生成检索查询和最终答复，现有 DSH 工具负责执行本地检索；工具结果进入后续模型请求时不再重复强制检索。

修复位置：[codex-app-server-bridge.ts](../../services/demo-gateway/src/backends/codex-app-server-bridge.ts)。回归测试覆盖明确中文检索请求、普通问诊不强制、当前回合已检索后不重复、严格结构化响应不覆盖。

## 必须保留的限制

- 修复后实际完整浏览器样本为 1 个明确 RAG 请求，观察值是 1/1；单个样本不足以证明总体稳定率。工具选择现在由本机桥接层对匹配到的请求确定性收紧，规则单测通过。
- 本次桥接 trace 显示 2 次强制 RAG 选择：一次位于显式证据请求，一次位于后续记忆回合。后者也额外检索了 3 条证据，但记忆召回仍正确完成。trace 为保护患者文本没有保存触发原文，因此无法从脱敏记录判定第二次匹配的具体词句；这是应继续收窄/核验的过触发风险，不计入“明确证据请求”成功率。
- 引用验收只核对编号与当前证据卡一致，不代表来源在语义上支持每条医学主张；语义支持率不可测。
- 延迟是单机小样本，不是生产 SLA。真实公网、高并发及持续负载不在本次范围。
- 两次早先看似“修复后”的试跑接到了旧 8333 进程，未加载本次桥接代码，故不计入修复结果。本报告只计算新进程的最终验收运行。
