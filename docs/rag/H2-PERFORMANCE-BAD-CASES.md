# H2 首轮性能与成本 Bad Case 登记

日期：2026-10-15  
范围：12 条 DEV 草案问题的现有 A–E* 运行，仅登记运行成本和性能问题。表中同一 query 在不同 arm 出现多次，因此这些是 11 个**执行层观察**，不是 11 个独立临床失败。相关性、证据适用性和最终回答质量均未经过 qrels 审核。

| # | Query / arm | 实测现象 | 归因 | 后续验证方向 |
|---:|---|---|---|---|
| 1 | H2-P-007 · BM25 | 3,869.7 ms；FTS 表达式命中 778,408 个 chunk | CJK 双字 bigram 被 OR 扩展，候选命中面过宽 | 在冻结 qrels 后比较受控的 CJK tokenizer/query expansion；同时观察 Recall 与延迟 |
| 2 | H2-P-008 · BM25 | 3,735.7 ms；命中 803,301 个 chunk | 与 P-007 相同的宽 OR 词项扩展问题 | 同上；不可单独为降延迟改查询而不重跑固定评测 |
| 3 | H2-P-007 · RRF | 4,194.4 ms | 当前 RRF 顺序执行 Dense 与 BM25，融合不会消除慢的 BM25 阶段 | 若保留混合检索，测并行执行与真实完整请求延迟；质量由同一 qrels 判断 |
| 4 | H2-P-008 · RRF | 4,095.6 ms | P-008 的 BM25 尾延迟沿用到 RRF | 同上 |
| 5 | H2-P-007 · RRF + BGE | 暖态分段求和 4,285.9 ms | Reranker 只重排候选，未减少前置 RRF 的耗时；P-007 主导该臂 P95 | 用固定候选重测端到端延迟，分开报 RRF、重排和冷启动 |
| 6 | H2-P-008 · RRF + BGE | 暖态分段求和 4,184.1 ms | 与 P-007 相同，前置稀疏检索构成主要尾延迟 | 同上 |

## 口径

- #5–#6 使用逐 query RRF 与 reranker stage latency 相加，是暖态分段求和，不是重新测得的端到端请求时间。逐题审计及 run 输入 SHA-256 见 Git-ignored `h2-pilot-v2/d-stage-latency-audit.json`。
- E* 是成本/可行性探针，当前无 qrels，因此不是经 DEV 质量评估选出的最终 E 消融臂。
- 以上结果不能说明 BM25、RRF、BGE 或 Iterative 的相关性更差；它们只说明当前实现和这次运行中观察到的成本热点。
- 相关性/覆盖 Bad Case 至少需要两份独立盲审标签和裁决；收到标签后需另建检索质量 Bad Case 表，不能将本表改名冒充质量失败。
