# PRD：合成患者多轮临床工作流模拟

**状态：** Draft
**产品目标：** 用可重复、可审计的合成患者会话，观察 Huiyi 工作流在接近真实使用节奏下的行为。它是工程验证与体验演示，不是临床有效性研究。

## 1. 问题与目标

当前单病例演示能说明界面和工具链如何工作，无法覆盖患者在多轮咨询中逐步补充信息、跨会话延续上下文、表达不清或出现风险信号等情况。本项目拟构造约 300 个合成患者档案，由独立的“患者模拟 Agent”按档案与状态规则进行多轮互动，用于验证工作流、上下文管理、安全边界和系统稳定性。

### 目标

- 生成并版本化约 300 个完全合成的患者档案和就诊情景。
- 支持 5–12 轮单次咨询和跨会话复诊流程；可固定随机种子进行回放。
- 对记忆连续性、澄清问题、证据引用、风险升级、患者隔离和服务稳定性形成可追溯评估。
- 让开发、临床审核者能查看患者档案、对话时间线、工具/证据元数据和失败原因。
- 端到端执行真实项目运行链路：DSH 根会话、MDAgents-derived 临床协作、AMA 患者记忆、i-MedRAG-derived 医学证据获取。

### 非目标

- 不从真实病历复制或改写患者资料，也不把 300 个模拟档案称作真实患者或临床试验样本。
- 不用模拟成功率证明诊疗准确性、临床安全性或医院上线许可。
- 不让患者模拟 Agent访问被测助手的隐藏思维、完整工具结果或评估答案。

## 2. 数据与模拟设计

### 患者档案

每个档案以结构化 JSON 存储，含合成 ID、年龄段、性别（如场景需要）、主诉、既往史、用药/过敏、就诊目标、沟通习惯、健康素养、记忆状态、需逐步披露的信息、风险触发条件和结束条件。每条临床事实都带 `synthetic=true`、生成器版本和场景版本。

300 个档案可先按约 12 个场景族、每族约 25 个档案分层生成，再按年龄段、慢病数量、用药复杂度、信息披露方式和沟通风格做覆盖矩阵。分层是覆盖计划，不代表患病率抽样。

### 患者模拟 Agent

患者模拟 Agent 只拿到当前患者档案及当前轮允许披露的事实。用状态机决定“主动提到什么、被问到什么才补充、哪些说法需要澄清”；模型只负责自然语言表达。临床事实、用药、时间顺序与风险触发由结构化状态约束，不能由模型自由编造。被测 Huiyi Agent 与评估器使用独立上下文。

### 被测系统端到端链路

每次会话都走与产品相同的 DSH 根 Agent/Session/AgentLoop；患者模拟器只生成合成输入，不代替 DSH，也不直接读取被测系统的隐藏状态。完整纵向情景应按以下顺序验证：

1. **身份与会话：** Simulation Lab 为每个合成患者和模拟临床用户建立受信测试身份。服务端把身份、合成患者、Encounter 和 DSH Session 绑定；模拟器不能用任意 `patientId` 或 `userId` 选择记忆。
2. **AMA：** DSH 根 turn 开始时按已解析的合成患者身份召回一次 turn-scoped `MemorySnapshot`。跨复诊记忆连续；MDAgents-derived 子 Agent 只读同一快照；只有成功完成的根 turn 可提交记忆。患者记忆不与检索证据合并。
3. **i-MedRAG-derived：** 根 Agent 通过 `search_medical_evidence` 触发 Health Engine 的有界迭代检索，证据带有来源和版本；检索计划文本不能伪装成证据。每轮记录证据 ID、corpus 版本、调用次数和耗时，不在普通轨迹中记录 evidence 正文。
4. **MDAgents-derived：** 根 Agent 根据复杂度选择是否调用有界临床协作。DSH 原生子 Agent 只接收完成任务所需的合成病例摘要、同一只读 MemorySnapshot 和已获取 EvidenceSet；子 Agent 无继承工具、无完整根对话，也不能自行召回/写入 AMA。结构化且成功完成的子结果才可供根 Agent 综合。
5. **根回答与提交：** 由 DSH 根 Agent 负责用户可见的最终回答；完成后再按 AMA 生命周期写入合成患者记忆。取消、失败或未完成 turn 不得产生记忆提交。

测试报告必须区分“已走过各组件链路”与“验证了临床准确性”。本项目将 MDAgents 和 i-MedRAG 实现标识为有界、经过适配的 derived workflow；不声称是上游论文的原样复现或临床有效性证明。

首批情景建议覆盖：常规复诊、信息不完整、记忆连续性、依从性困难、多病共存、药物核对、焦虑/低健康素养、前后表述不一致、超出系统能力的问题、红旗症状与紧急升级、取消/恢复和会话隔离。

## 3. 运行和评估

一次运行由固定的 `patientId + scenarioVersion + seed + systemVersion` 标识。记录每轮输入输出、结构化事件、工具调用状态、检索证据 ID/来源、延迟、取消/错误状态和评估结果。默认执行轨迹只存脱敏结构化元数据；完整合成对话如需保存，进入明确标记的合成测试存储，并设置保留期限。

评估分层进行：

1. **确定性规则：** 必要澄清点、不可越过的风险处理、是否编造患者资料/检索来源、会话与身份隔离、超时和取消行为。
2. **模型评估：** 对沟通完整性、上下文连贯性和证据相关性给出结构化评分与理由；评分不能替代规则检查。
3. **临床审核：** 先人工审阅小规模试点中的所有档案与关键失败，再对 300 档案分层抽样并复核所有高风险、冲突和评估不一致案例。

主要指标包括：档案事实一致率、必要澄清覆盖率、证据来源/引用匹配率、风险升级召回、无依据临床断言数、跨患者串扰数、跨会话记忆正确率、完成率、取消后资源释放、P50/P95 延迟和每轮推理成本。高风险情景的安全规则采用零容忍门槛；总体分数不得掩盖单个高风险失败。

### 必须单列的隐私与链路门槛

- **组件覆盖：** 每个完整 E2E 用例标记 DSH、AMA、i-MedRAG-derived、MDAgents-derived 的调用/跳过原因；端到端验收集须至少覆盖“无协作简单复诊”“协作复杂病例”“有历史记忆的复诊”“检索无结果/失败”“取消与恢复”。
- **记忆隔离：** 患者 A 的合成记忆不得出现在患者 B 的召回、提示或 Agent Activity 中；不同模拟临床用户访问同一患者时也必须按授权测试。测试至少覆盖两个患者并发、多 Session 同患者、取消后重试、会话 ID 重放和越权患者 ID。
- **协作边界：** 子 Agent 只能获得最小必要的结构化合成病例上下文、同一只读记忆快照和受限证据；拒绝/失败/取消的子任务不得贡献医疗结论，也不得写记忆。
- **证据与记忆分离：** 评估器分别校验记忆来源与证据来源；记忆不能充当外部医学引用，模型生成的查询或摘要不能标为检索命中。
- **无 PHI 运行：** 300 档案全部由结构化合成生成，不从生产 EMR 脱敏或改写。未来真实患者 E2E 必须另有机构批准的数据源、登录身份、患者授权和审计实现；当前 Simulation Lab 不连接 EMR。
- **结构化审计：** 默认只持久化主体/患者/Encounter/Session 的内部关联 ID、组件状态、调用次数、Evidence ID、延迟、结束原因和授权判定；会话正文、完整记忆、evidence 文本、完整回答和提示词不进入通用 trace/遥测。

## 4. 产品呈现

建议做独立的 **Simulation Lab（模拟评测台）**，与日常临床工作台分开，并在整个模拟区持续标明“合成数据 / 非真实患者”。

- **运行总览：** 300 档案按场景族、风险等级、运行状态筛选；显示通过、待复核、失败和高风险告警数量。
- **患者档案：** 合成患者卡、结构化病史、事实披露策略、风险触发条件和版本信息。
- **会话回放：** 多轮时间线，分开展示患者陈述、Huiyi 回答、工具/证据事件和评估注释；支持逐轮播放、暂停和对照不同系统版本。
- **结果对比：** 以场景和指标比较两次运行；高风险失败可直接定位到具体轮次和触发规则。
- **审核队列：** 汇总规则失败、模型/规则意见不一致、无证据断言和红旗漏报，供临床审核者处理。

生产临床工作台不显示模拟患者；模拟评测台不得连接生产 EMR，也不得让模拟 Agent 读取生产患者上下文。

## 5. MVP 计划与验收

### 阶段 A：档案与协议

- 定义 JSON Schema、场景标签、风险分类、版本和随机种子协议。
- 建立生成后校验和人工审核流程；先做约 30 个档案，覆盖每类关键场景。
- 验收：重复同一版本与 seed 可得到一致的状态转移；档案没有真实个人信息；临床审核者能发现并纠正结构化事实错误。

### 阶段 B：模拟执行器

- 接入独立患者模拟 Agent，控制每轮允许披露的信息和最大轮数。
- 支持暂停、取消、回放、重跑和故障恢复；模拟和被测系统使用分离的 Session。
- 将 DSH、AMA、i-MedRAG-derived 和 MDAgents-derived 链路接入可观测的合成病例 E2E harness；组件不可用时明确标记为未覆盖，不得静默用 fixture 结果冒充通过。
- 验收：取消/超时不继续写后续轮；两个患者运行之间没有状态串扰；日志默认无原始文本。
- 验收：跨复诊召回只回到同一个合成患者；子 Agent 使用同一只读快照且没有继承工具；检索证据与患者记忆在接口和报告中分开。

### 阶段 C：评测台与 300 档案

- 完成档案列表、回放、指标总览和审核队列；临床审核通过后扩充至 300 档案。
- 验收：按版本/场景/风险筛选；每个汇总分数可追溯到档案、轮次、规则和系统版本；高风险失败不可被平均分隐藏。
- 全量 300 档案长跑作为离线/手动验收批次，不放进每次快速 CI；报告包含实际组件调用覆盖、模型/索引版本、重试和资源成本。

## 6. 治理与限制

模拟数据生成来源、提示词、模型版本、审核人、规则版本和数据保留期均需留档。禁止从生产 EMR 导出后“脱敏生成”模拟患者，除非另有正式批准的数据治理方案。界面和报告都需注明模拟结果只用于工程测试、产品体验和缺陷发现，不构成临床验证或诊疗建议。
