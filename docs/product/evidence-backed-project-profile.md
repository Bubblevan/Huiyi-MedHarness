## 可用项目简介草稿

**慧宜 MedHarness｜互联网医院复诊与医生辅助决策的临床 Agent 工作台｜[个人角色待确认]**

面向复诊咨询中患者历史难以连续使用、医学资料分散和复杂病例需要协作分析的问题，构建以 DSH 为单一用户回合运行时的临床工作台原型，目标是在受信患者/Encounter 上下文、患者纵向记忆和可追溯医学证据基础上辅助完成连续咨询，并把结构化摘要/病历草稿交由医生审核。

- 历史本机配置曾接通 DSH、Qwen3-8B、Health Engine 本地 RAG、AMA 合成记忆及 MDAgents-derived 受限协作；该配置不属于当前 GPT-6-Luna-only 实验。当前 Luna 路线已通过认证合成 smoke、DSH→iterative RAG smoke、两次单病例 8 轮双 Encounter 配对工程 pilot，以及一次同 Encounter 严格组合 smoke（advanced MDT 7/7 child、AMA 与 iterative RAG 均完成）。首轮曾在 AMA Encounter commit 处撞上 pinned wrapper 的固定 60 秒请求超时；将其改为可配置且本机评测设为 90 秒后，使用同一单病例配对设置重跑，DSH 主轮次 16/16 完成、AMA 两次 commit 成功、10 次 AMA 模型调用 0 失败。集成组观察到 7 个协作子运行和一次本地 single RAG；其 P95 延迟约 131 秒。独立 namespace 隔离探针另有 pass 记录，但新配对 run 自身未重跑该探针。以上是工程信号，不是病史正确率或临床任务成绩；新旧配对结果的临床指标仍因盲审/病例审批未完成而为 `null`。
- 按 DSH root turn 集中处理记忆召回与提交，并将患者历史和外部医学证据分开；合成临床评测 Gateway 已有登录、tenant/access-group 患者范围、Encounter 绑定和会话所有权校验；生产患者身份、Encounter 授权和真实 EMR 接口仍待实现。
- 建立 RAG、Memory、协作和推理性能分项评测资料；统一连续复诊任务的 A/B 对照、风险复核和患者隔离评测仍在规划中。
