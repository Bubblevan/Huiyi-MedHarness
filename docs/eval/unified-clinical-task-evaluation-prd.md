# 统一临床任务评测 PRD

**状态：** Draft / 尚未执行统一全量评测
**范围：** 全部使用经审核的合成患者与合成就诊数据；评测工程工作流，不证明临床有效性、诊疗安全性或上线许可。

## 1. 目标

评估 Huiyi 是否能在了解患者历史、当前 Encounter 和医学证据的条件下，辅助完成一次连续复诊咨询，并输出供医生审核的结构化摘要/草稿。任务不是比较泛化医疗问答分数，也不是用单一医学选择题成绩替代业务闭环。

统一评测回答六个问题：

1. 本次复诊的关键流程任务是否完成？
2. 必要历史事实是否正确召回，是否发生错误引用？
3. 医学判断中的可核实断言是否有相关且正确的来源支撑？
4. 红旗信号和必要升级是否识别？
5. 不同患者、临床用户和 Session 之间是否严格隔离？
6. 端到端耗时、调用量、成本和资源占用是否可接受？

## 2. 合成患者与就诊环境

每个患者档案有稳定的合成 `patientId`、场景版本和随机种子，包含结构化病史、历史 Encounter、症状变化、检验/检查、用药/过敏、就诊目标、需逐步披露的事实、红旗触发条件和结束规则。生成事实须带合成标识、生成器版本及审核状态。

患者模拟 Agent 只接收本轮允许披露的事实，由状态机决定主动陈述、追问后补充、澄清和风险触发；语言模型只负责表达，不得改写受约束事实。患者模拟、被测系统、规则评分器和人工审核各自使用隔离上下文。禁止读取或改写真实 EMR 来生成合成档案。

### 分阶段规模

| 阶段 | 规模 | 用途 | 放行条件 |
| --- | ---: | --- | --- |
| A | 约 30 名合成患者 | 调试档案 Schema、事实披露状态机、事件协议和隔离 | 档案审核完成；同 seed 可回放；关键风险规则通过。 |
| B | 约 60–80 名 | 验证场景覆盖、流程评分一致性、组件失败与重试 | 预先冻结本阶段范围；完成错误归因；高风险问题关闭或记录为阻断。 |
| C | 目标约 300 名 | 冻结系统版本后的离线全量长跑；保留独立测试患者/场景 | 临床审核通过；训练和选型不得使用独立测试集；资源预算有实测依据。 |

不在早期直接对 300 名患者跑数千轮。患者数、轮数和实际完成量必须由运行 manifest 报告，不能把计划规模写成已完成规模。

## 3. 对照组与实验组

所有组使用完全相同的患者档案、逐轮披露计划、用户任务、停止条件和评分规则。固定模型版本、采样配置、提示模板和最大输出限制；任何差异都写入 manifest。

| 组别 | 配置 | 解释 |
| --- | --- | --- |
| A：单 Agent 对照 | Qwen3-8B 单 Agent；只接收本轮用户陈述及当前就诊最小上下文；不使用外部 RAG、AMA 长期记忆或专科协作。 | 业务基线。不可把上游论文数值代入本地结果。 |
| B：集成基线 | 当前 Qwen3-8B + DSH + 本地 RAG + AMA + MDAgents-derived 受限协作。 | 隔离工具链/患者连续性相对单 Agent 的增益与代价；保持 Qwen3-8B 权重不变。 |
| C：后训练实验组 | 与 B 相同的 DSH/RAG/AMA/协作配置，替换为通过审阅的 SFT 或 RL 候选模型。 | 目标实验组；只有训练真实完成且模型固定后才能运行。当前训练 canary 和提升评测尚未完成，因此此组为待执行，不得用 B 冒充。 |

B 与 C 的运行须共享患者集合、用户任务和评估配置。先在训练/开发集定位错误、形成可追溯训练样本，再用冻结验证集选型；独立测试集只在方案冻结后运行一次或按预注册协议运行。记录 SFT 与 RL 各自的模型哈希、数据版本和训练配置。

## 4. 业务指标与计算口径

每道任务须有患者事实清单、必要澄清点、医学证据判定表、风险规则和医生审核评分表。以患者/病例为统计单元，同时报告逐项明细、宏平均、分布和置信区间；不允许平均分掩盖高风险个案。

| 维度 | 指标 | 计算/记录口径 |
| --- | --- | --- |
| 临床任务 | 复诊流程关键任务完成率 | 满足预先定义的关键任务数 / 应完成关键任务数；另报病例级“全部关键任务通过”比例。任务清单由临床审核者在运行前冻结。 |
| 病史连续性 | 关键历史事实召回准确率 | 被正确引用的必需历史事实 / 该任务需要的历史事实；同时报告漏引和矛盾引用。 |
| 病史连续性 | 错误历史引用率 | 错误或归属不明的患者历史断言 / 被审阅的历史断言；跨患者串扰另按次数与受影响患者数报告。 |
| RAG 循证 | 证据支持率 | 有相关、可追溯来源支撑的医学断言 / 抽样审阅的医学断言。无来源、仅有检索计划或不相关命中均不计为支持。 |
| RAG 循证 | 正确引用率 | 引文与来源身份、段落内容和相应断言均匹配的引用数 / 被检查引用数。 |
| 风险识别 | 风险信号召回率 | 被正确识别并按预设处置升级的高风险信号 / 档案中实际出现的高风险信号。逐病例列出漏报。 |
| 多 Agent | 复杂病例关键信息覆盖率 | 最终答复包含的病例必需分析点 / 预先冻结的必需分析点；并记录额外子运行、模型调用、token 与耗时。 |
| SFT/RL | 冻结测试集医学正确率、格式合规率 | 仅在 C 组训练真实完成后评测；规则评分和临床审阅分开报告。报告错误率、分母和区间，不从开发集挑选结果。 |
| 部署 | 端到端 P50/P95、并发完成率、成本 | 从收到本轮请求到 DSH root turn 完成；记录失败、取消、重试、调用数、token、设备与并发配置。比较必须使用相同任务集。 |
| 权限 | 权限违规次数、跨患者串扰次数 | 按越权访问尝试、实际返回数据、写入副作用分别记录；任何实际患者数据越权均单独阻断，不用总体分数抵消。 |

性能结果（例如 HC-PERF-001 的模型/流水线耗时）与临床任务结果分开呈现。当前 45 题 MedQA 及 LoCoMo 结果仍是各自基准的结果，不等价于复诊工作流能力。

## 5. 错误归因与模型迭代

每个失败必须关联患者、Encounter、轮次、组件版本、用例规则和复核结论，至少归入：

- **证据缺失：** 未检索、无结果被当作结果、证据相关性不足、来源或引用错误。
- **病史遗漏：** 必需历史未召回、时间线错误、矛盾记忆未指出、患者身份混淆。
- **临床推理：** 事实已提供且证据可用，但风险或判断不正确；交临床审核复核。
- **协作失败：** 协作不必要/漏调用、子任务信息不足、失败结果进入综合答案、额外调用无收益。
- **执行错误：** 工具/schema 错误、超时、取消未清理、权限失败、重复写入或格式错误。

迭代链路：逐题复核 → 选择训练/提示/检索修复方式 → 记录修复假设和数据来源 → 在开发集实现 → 在冻结验证集比较 → 固定候选 → 在独立测试集复评。修复样本不得泄露到对应独立测试集；高风险案例必须人工复核。若训练依赖和 canary 未通过，SFT/RL 阶段保持 blocked，不宣称能力增益。

## 6. 端到端覆盖要求

每个 E2E 用例都记录 DSH root Session/AgentLoop、RAG、AMA、MDAgents-derived 协作的调用状态及跳过原因。至少覆盖：普通复诊、信息不足需澄清、跨复诊记忆、复杂病例协作、RAG 无结果/失败、风险升级、事实冲突、取消恢复、同患者多 Session、跨患者并发和越权患者 ID。

目标实验组必须使用同一次真实 DSH AgentLoop 完成工具调用到最终回答。组件单测、直接 HTTP 请求或 fixture 后端运行不能计为集成组 E2E 通过。被测与模拟 Agent 使用分离 Session；子 Agent 只得到最小必要的结构化合成上下文、同一只读 MemorySnapshot 和 EvidenceSet。

## 7. 安全、审计与呈现

- Simulation Lab 与临床工作台分离，持续标记“合成数据 / 非真实患者”；生产临床 UI 不显示模拟患者。
- 通用 Execution Trace 只保留经 allowlist 筛选的脱敏元数据；不记录原始患者陈述、完整回答、完整记忆、evidence 正文或提示词。
- 合成对话如用于评审，进入隔离的合成测试存储，限制访问、用途和保留期；不要放入通用 telemetry。
- 临床审核者需能查看高风险失败、关键事实、来源匹配和逐题错误归因；评分模型不能代替临床审核。
- 测试/模拟 Agent 不得连接生产 EMR，不得拥有读取真实患者记忆或写回临床记录的工具。

Simulation Lab 可以呈现 cohort 状态、患者档案、逐轮回放、版本对比和审核队列；概览需点击回到患者/轮次/规则，展示分母和被跳过的组件，不能只显示综合分。

## 8. 尚未完成的基线

截至本 PRD 编写时，仓库记录了有限本机合成患者 E2E；没有完成 30/60–80/300 阶段的统一运行、基线/集成组配对评分、临床审核集、正式模型训练、后训练对比或生产授权测试。每一阶段完成后更新 manifest 和审计报告再改变状态；本文件中的人数和能力均为计划，不是成绩。
